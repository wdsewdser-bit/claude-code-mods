# ctx-mod

Claude Code mod（function hooks 插件）：让长会话跨多个上下文窗口继续干活，而不靠模型写摘要。它给模型一本任务账本和一份可检索的完整历史，换窗口时由代码拼出交接信息，不调用模型。

状态：实验性，0.1.0。针对 Claude Code 2.1.29x 的 Mods API 开发和测试。给模型看的工具说明和交接文字目前是中文。

## 它做什么

- **任务账本**：模型每完成一个阶段记一条（任务、状态、下一步、接下来要改的位置）。标 `done` 必须附上能证明它的工具结果编号。
- **完整历史**：用户消息、助手回复、工具结果都按编号落盘。工具结果末尾会带上 `[#123]` 这样的编号，模型之后可以按编号读原文，或按关键词、工具名、文件、窗口搜索，不用重跑同样的命令。
- **零摘要换窗**：上下文快满时，用账本和磁盘上的最新文件内容生成交接信息，直接开新窗口。交接里有最近的用户请求、进行中的任务和下一步、待改位置的文件片段、文件工作集、最近的动作、子代理名单。
- **换窗的门槛**：账本太旧、写盘失败、刚换过窗口时不换，或者退回引擎自己的摘要，并把原因告诉模型。

## 安装与启用

依赖 [cache-keeper](../cache-keeper)（读它记录的缓存状态），两个都要装：

```
/plugin install cache-keeper --marketplace wdsewdser-bit/claude-code-mods
/plugin install ctx-mod --marketplace wdsewdser-bit/claude-code-mods
```

装好后默认什么都不做。只有启动 Claude Code 时带着环境变量 `CTX_MOD=1`，它才会注册工具并接管换窗：

```
# macOS / Linux
CTX_MOD=1 claude

# Windows PowerShell
$env:CTX_MOD = '1'; claude
```

## 模型得到的工具

| 工具 | 作用 |
| --- | --- |
| `context` | `status` 报告上下文用量、距上次换窗的请求数、本小时换窗次数；`new` 申请换窗口 |
| `ledger_append` | 追加一条账本记录：`task_id`、`status`（`in_progress` / `done` / `superseded` / `blocked`）、`text`、`next_step`、`anchors`、`evidence` |
| `ledger_read` | 读账本：首页、当前窗口的全部条目、归档页，或按词搜索 |
| `history` | `search` 按词、角色、工具名、文件、窗口、入口查历史编号；`read` 按编号读原文或那次工具调用的完整参数 |

mod 还会在系统提示里加一段说明，告诉模型这些工具怎么配合使用。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/ctx-mod` | 显示是否启用和当前用量 |
| `/ctx-mod switch` | 立即换到新窗口，不调用模型 |

## 什么时候换窗

默认按 40 万 token 的窗口算，到 75%、83%、88%（30 万、33.2 万、35.2 万）时分三级提醒模型先记账再换窗。故意放得晚：换窗会丢掉工作细节，所以尽量把一个窗口用完。

- 模型自己申请换窗，要求距上次换窗至少 30 次模型请求，每小时最多 4 次，且最新一条账本记录之后的工具结果不超过 5 个。
- 引擎自动压缩时由 mod 接管，用交接信息代替摘要。账本落后太多（超过 25 个没记账的工具结果）时把摘要交还给引擎。
- 缓存已经过期、上下文又超过 10 万 token 时，下一条用户消息会先触发换窗再处理，因为反正要整段重写缓存。
- 上下文超过 12 万 token 时，加载会重建缓存的工具组之前先换窗。
- 5 小时额度用到 90% 以上时，换窗后不会自己接着干，等用户发话。

这些数字都在 `hooks/lib/types.ts` 的 `DEFAULTS` 里。

## 数据放在哪

每个会话一个目录：`~/.claude/ctx-mod/<session-id>/`

| 文件 | 内容 |
| --- | --- |
| `history-wNNN.jsonl` | 第 N 个窗口的历史，一行一条 |
| `ledger.jsonl` | 当前这一页账本 |
| `archive-NNN.jsonl` | 翻页归档的账本 |
| `handoff-wNNN.md` | 进入第 N 个窗口时的交接信息原文 |
| `events.jsonl` | 每次换窗的记录 |
| `meta.json` | 编号、窗口号、文件活动等状态 |

这些文件含有会话的全部内容，包括工具输出。mod 不会把它们发到任何地方，也不会自动清理。

## 已知限制

- 助手在回合中间、工具调用之前说的话，有一部分在引擎里是思考块，不会进历史。每回合最后的正式回复不受影响。
- 换窗只保留账本里记下的东西和磁盘上的文件。模型没记账的中间结论会丢，所以账本太旧时 mod 会拒绝换窗。
- 请求数、窗口大小等判断依赖引擎的事件，引擎版本变了可能要跟着改。

## 开发

```
claude plugin validate .
claude plugin test .
npx -p typescript tsc -p .
```

`.claude-plugin/types/` 是引擎加载 mod 时生成的类型定义，不入库。从磁盘加载开发中的 mod：`claude --plugin-dir <这个目录>`。
