# away-autopilot

用户离开时不让会话卡在“等你确认”：模型在回复末尾单独写一行 `[待确认]`（桌面端用 `wrap_up` 的 `ask` 提问也算），默认 5 分钟后用户本人还没回复，插件就往会话里推一条提示，让模型自行决定、继续推进。

- **等待阈值（`idleMinutes`，默认 5 分钟）**：`turn.complete` 之后起一个定时器；期间用户本人发来消息就取消（`prompt.submit` 的来源是 plugin、task-notification、scheduled-trigger、peer 等不算用户本人，ctx-mod 以用户身份重投的算）。触发时注入的提示限定：只做只读、无副作用、可回滚的改动；不做 commit/push、发送消息、删数据、改生产或共享配置、花钱；做完汇报替用户选了哪个、为什么、怎么回滚。
- **`[待确认]` 标记**：只有在看到这个标记（或桌面端的 ask 提问）之后才计时，普通结束不算等待用户。
- **`pause` 工具**：`mcp__away-autopilot__pause`（参数 `reason`）让模型在“剩下的都必须用户确认”时停下；暂停后不再自动推进，状态栏显示“离开模式：已暂停”，直到用户本人回复。
- **兜底上限（`maxAutoNudges`，默认 8）**：一次离开里最多自动推进这么多次，防止模型一直不调 `pause` 时无限循环；设为 0 表示不自动推进；用户本人一回复计数清零。

提示文本（`NUDGE` / `SECTION`）就在 `hooks/register.ts` 里，改完不需要 build。

## 配置

安装时的设置页或 `/plugin` 的配置菜单里改：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `idleMinutes` | 5 | 等待多少分钟后提示；允许小数，范围 0.5–240 |
| `maxAutoNudges` | 8 | 一次离开最多自动推进几次；范围 0–50，0 = 不自动推进 |
| `enabled` | true | 为 false 时不注册 `pause` 工具、不加系统提示段、不起定时器 |

越界或非法的值回退默认，读配置失败也回退默认，hook 不会因此抛错。提示文字里的等待时长按 `idleMinutes` 生成：整数显示为“5 分钟”，非整数显示一位小数（如“0.5 分钟”）；默认配置下与 0.1.0 的文本逐字相同。
